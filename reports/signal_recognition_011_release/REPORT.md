# 0.1.1 发布记录

已发布 `weitaoccc/signal-recognition:0.1.1`，平台 linux/amd64。远端摘要与本地通过容器验证的版本一致，匿名访问核验通过。

```bash
docker pull weitaoccc/signal-recognition:0.1.1
```

## 更新内容

- 调制识别从 13 类扩展到 20 类，新增 OQPSK、DBPSK、DQPSK、MSK、GMSK、32QAM、256QAM。
- 每条信号最多五个 2048 点窗口，平均 softmax 分数；最大平均分数 ≥0.5 输出类别，<0.5 输出字符串 `"unknown"`。
- 过短或无有效功率继续返回 `null`，公共响应不返回分数。
- 接收机增加新增类别和 unknown 的映射、显示。预处理、请求字段、接口路径及编号关联方式保持原样。
- GitHub 提供源码与文档，不再提交权重；Docker 镜像内置推理权重。

## 仿真测试

独立测试 35000 条，其中 15～30 dB 为 20000 条，均为 I/Q 两通道、2048 点输入。

| 范围 | 不按分数筛选的准确率 | 0.5 阈值保留率 | 保留结果正确率 |
|---|---:|---:|---:|
| 0～30 dB | 71.9029% | 80.64% | 82.32% |
| 15～30 dB | 79.4050% | 90.12% | 83.98% |

这些是仿真指标。OFDM 的训练结构已扩充，真实回归中 OFDM→AM 明显减少；DBPSK、高阶 QAM 和 AM/SSB 仍有混淆。unknown 是低分拒绝，保留正确率不代表未知类别检出率。

## 容器完整流程

两条实采数据各选 front、middle、back 三个 100 帧窗口，共六个窗口，完成：

```text
原始 IQ → 强度矩阵 → 检测 HTTP → 外部逐框预处理 → 分类 HTTP → 编号关联
```

- 六个窗口的 TF 检测经 STFT 时间原点对齐后，与原记录一致；原 IQ 检测入口也通过回归。
- 共 143 个检测框，142 条 IQ 成功提交；另 1 个框因原有频率边界限制未能预处理。
- 142 条预处理 IQ 与原记录逐字节一致，容器输出与本地 0.5 阈值结果逐条一致。
- 分类响应包含 OFDM 106、unknown 5、null 24，以及其他类别 7 条。
- 本机预热后的顺序流程为每窗口约 0.45～0.76 秒，包含 TF 计算、检测 HTTP、外部预处理及分类 HTTP，不包含磁盘读取和绘图。
- 就绪接口、容器健康检查、空批次、过短/零功率和 400/413 错误处理通过。
- GitHub 更新前 259 项自动测试通过；测试中的模型检查点使用临时生成参数，无需下载权重文件。

2.4 GHz 数据沿用 307.2 MS/s 暂定采样率。实采数据无完整调制标注，这里报告流程和相同输入回归结果，不给出真实分类准确率。原 IQ、完整逐框输出和日志保留在本地。
